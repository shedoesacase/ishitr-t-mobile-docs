# 1. Введение
Этот документ описывает пользовательский интерфейс (UI) и сценарии взаимодействия с админ-панелью сервиса-генератора. Документ предназначен для фронтенд-разработчика (для реализации интерфейса) и QA-инженера (для написания тест-кейсов).

# 2. Общая структура интерфейса
Интерфейс представляет собой одностраничное веб-приложение (SPA) с боковой или верхней навигацией по 4 основным вкладкам:
1. **Дашборд** (Обзор состояния системы)
2. **Управление временем** (Virtual Clock)
3. **Эмуляция событий** (Генерация трафика и спец. сценарии)
4. **Справочники** (Управление тарифами)

Глобальный хедер (виден на всех вкладках):
- Индикатор "Реальное время": `[ДД.ММ.ГГГГ ЧЧ:ММ:СС]`
- Индикатор "Виртуальное время": `[ДД.ММ.ГГГГ ЧЧ:ММ:СС]` (выделен цветом, если `multiplier > 1` или `is_paused == true`)
- Статус генерации: `[Активна]` / `[На паузе]`

# 3. Детальное описание вкладок и сценариев

## 3.1. Вкладка "Дашборд"
**Цель:** Быстрый обзор текущих сущностей в системе, чтобы понимать, кому можно назначать генерацию событий.

**Элементы интерфейса:**
1. **Карточки времени** (дублируют глобальный хедер, но с кнопкой "Перейти к управлению").
2. **Таблица "Пользователи"**:
   - Колонки: ID, Номер телефона, Имя, ID группы, Роль, Статус.
   - Действие: Кнопка "Обновить" (вызывает `GET /api/v1/users`).
3. **Таблица "Семейные группы"**:
   - Колонки: ID группы, ID владельца, Статус, Кол-во участников, Дата создания.
   - Действие: Кнопка "Обновить" (вызывает `GET /api/v1/groups`).
   - Действие: Нажатие по группе разворачивает ее в выпадающий список с участниками группы (Таблица с колонками, как в таблице "Пользователи").
1. **Таблица "Тарифы"**:
   - Колонки: ID, Название, Трафик (ГБ), Минуты.
   - Действие: Кнопка "Обновить" (вызывает `GET /api/v1/tariffs`).

**Сценарий взаимодействия (Загрузка данных при открытии вкладки):**
1. Пользователь открывает вкладку "Дашборд".
2. **Система (Генератор):**
   - Автоматически выполняет 3 параллельных GET-запроса к Backend Core API: `/api/v1/users`, `/api/v1/groups`, `/api/v1/tariffs`.
   - Отображает данные в соответствующих таблицах.
3. На экране отображаются актуальные данные из системы.
4. Если список пуст, отображается заглушка: *"Нет данных. Перейдите во вкладку 'Справочники' для создания тарифа или создайте пользователей и группы через мобильное приложение"*.

**Сценарий взаимодействия (Ручное обновление данных):**
1. Пользователь нажимает кнопку `[Обновить]` над одной из таблиц.
2. **Система (Генератор):**
   - Выполняет соответствующий GET-запрос к Backend Core API.
   - Обновляет данные в таблице.
3. На экране отображаются актуальные данные. Появляется toast-уведомление: *"Данные обновлены"*.
4. При ошибке (500 Internal Server Error): Появляется toast-уведомление: *"Ошибка загрузки данных. Попробуйте позже"*.

## 3.2. Вкладка "Управление временем"
**Цель:** Управление виртуальным временем (Virtual Clock) для ускорения тестирования временных триггеров (смена периода, аномалии).

**Элементы интерфейса:**
1. **Блок текущего статуса**: Крупно отображает `virtual_time`, `multiplier` и статус `is_paused`.
2. **Поле ввода "Множитель времени"**: Числовое поле (min=1, например, 10, 100, 1000).
3. **Кнопки действий**:
   - `[Ускорить время]
   - `[Сбросить в реальное время]`
   - `[Пауза]` / `[Возобновить]` (Toggle, меняет текст и цвет в зависимости от статуса).

**Сценарий взаимодействия (Ускорение времени):**
1. Пользователь вводит в поле "Множитель времени" значение `1000`.
2. Нажимает кнопку `[Ускорить время]`.
3. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/time/accelerate` с введенным значением множителя.
4. При успешном ответе (200 OK):
   - Поле множителя блокируется.
   - Индикатор "Виртуальное время" начинает быстро меняться (обновление каждую секунду).
   - Появляется toast-уведомление: *"Время ускорено в 1000 раз"*.
5. При ошибке (400 Bad Request): Под полем ввода отображается текст ошибки от сервера.

**Сценарий взаимодействия (Сброс времени):**
1. Пользователь нажимает кнопку `[Сбросить в реальное время]`.
2. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/time/reset`.
3. При успешном ответе (200 OK):
   - Поле множителя разблокируется.
   - Индикатор "Виртуальное время" синхронизируется с реальным временем.
   - Появляется toast-уведомление: *"Время сброшено до реального"*.

**Сценарий взаимодействия (Пауза):**
1. Пользователь нажимает кнопку `[Пауза]`.
2. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/time/pause`.
3. При успешном ответе (200 OK):
   - Глобальный статус меняется на `[На паузе]`.
   - Фоновая генерация событий временно приостанавливается.
   - Виртуальное время останавливается.
   - Кнопка меняет текст на `[Возобновить]` и цвет на зеленый.
   - Появляется toast-уведомление: *"Генерация приостановлена"*.

**Сценарий взаимодействия (Возобновление):**
1. Пользователь нажимает кнопку `[Возобновить]`.
2. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/time/resume`.
3. При успешном ответе (200 OK):
   - Глобальный статус меняется на `[Активна]`.
   - Фоновая генерация событий возобновляется.
   - Виртуальное время продолжает идти.
   - Кнопка меняет текст на `[Пауза]` и цвет на серый.
   - Появляется toast-уведомление: *"Генерация возобновлена"*.

## 3.3. Вкладка "Эмуляция событий"
**Цель:** Запуск фоновой генерации или мгновенных сценариев потребления для проверки бизнес-логики. Генератор публикует события напрямую в Брокер сообщений согласно контракту `Broker_Events_Contract`.

**Элементы интерфейса:**

1. **Выбор цели**: 
   - Переключатель "Режим: Для пользователя / Для группы".
   - Если "Для пользователя": Выпадающий список "Группа" → Выпадающий список "Пользователь" (зависимые списки, пользователь фильтруется по выбранной группе).
   - Если "Для группы": Выпадающий список "Группа".
2. **Блок "Фоновая генерация"**:
   - Переключатель режима: `[Простой (интервал)]` / `[Реалистичный (профиль)]`.
   - Если "Простой": поле ввода "Интервал (сек)" (min=1, default=5).
   - Если "Реалистичный": выпадающий список "Профиль" (Standard, Trip). 
   - Кнопка: `[Старт]` (запускает фоновую генерацию).
3. **Блок "Мгновенные действия"** (карточки с кнопками):
   - `[Списать X ГБ/мин мгновенно]` (с полем ввода объема).
   - `[Запустить аномалию]`.
   - `[Отправить запоздалое событие]` (с полем ввода "часов назад" и полем ввода объема).
4. **Таблица "Активные генерации"**:
   - Отображает запущенные фоновые потоки и аномалии.
   - Колонки: Пользователь/Группа, Тип, Режим, Статус, Запущено в, Действия.
   - Действия: Кнопка `[Стоп]` (вызывает метод остановки потока генерации).

---

**Сценарий взаимодействия (Запуск фоновой генерации в режиме "Простой"):**
1. Пользователь выбирает в переключателе "Для пользователя".
2. Выбирает в выпадающих списках: Группа "Семья Ивановых" → Пользователь "User #123 (+79991234567)".
3. В блоке "Фоновая генерация" переключает режим на `[Простой (интервал)]`.
4. Вводит в поле "Интервал" значение `60` (секунд).
5. Нажимает кнопку `[Старт]`.
6. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/events/background/user/start` с выбранными параметрами (user_id, resource_type, mode, interval_seconds).
   - Начинает внутренний таймер, который каждые 60 секунд формирует и публикует в брокер событие `ConsumptionEvent` с небольшим случайным объемом (например, 0.01-0.05 ГБ).
7. На экране появляется toast-уведомление: *"Фоновая генерация запущена для User #123"*.
8. В таблице "Активные генерации" появляется новая строка:
   - Пользователь: User #123 (+79991234567)
   - Тип: Фоновая
   - Режим: SIMPLE (60 сек)
   - Статус:  Активна
   - Запущено в: [текущее виртуальное время]
   - Действия: Кнопка `[Стоп]`

**Сценарий взаимодействия (Запуск фоновой генерации в режиме "Реалистичный"):**
1. Пользователь выбирает пользователя (как в предыдущем сценарии).
2. В блоке "Фоновая генерация" переключает режим на `[Реалистичный (профиль)]`.
3. Выбирает в выпадающем списке "Профиль" значение `TRIP` (симуляция поездки).
4. Нажимает кнопку `[Старт]`.
5. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/events/background/user/start` с выбранными параметрами (user_id, resource_type, mode, profile_type).
   - Начинает генерацию с минимальной интенсивностью (1 событие в несколько виртуальных часов), имитируя отсутствие активности.
1. На экране появляется toast-уведомление: *"Фоновая генерация запущена (режим: Поездка)"*.
2. В таблице "Активные генерации" появляется новая строка:
   - Пользователь: User #123 (+79991234567)
   - Тип: Фоновая
   - Режим: Поездка
   - Статус: Активна
   - Запущено в: [текущее виртуальное время]
   - Действия: Кнопка `[Стоп]`

**Сценарий взаимодействия (Остановка фоновой генерации через таблицу):**
1. Пользователь видит в таблице "Активные генерации" строку с User #123.
2. Нажимает кнопку `[Стоп]` в этой строке.
3. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/events/background/user/stop` с ID выбранного пользователя.
   - Останавливает событие, генерация дальше не продолжается.
1. На экране появляется toast-уведомление: *"Фоновая генерация остановлена для User #123"*.
2. Строка удаляется из таблицы "Активные генерации".

**Сценарий взаимодействия (Мгновенное списание):**
1. Пользователь выбирает пользователя "User #123".
2. В блоке "Мгновенные действия" нажимает карточку `[Списать X ГБ/мин мгновенно]`.
3. Вводит объем: `5` ГБ.
4. Нажимает кнопку `[Списать]`.
5. **Система (Генератор):**
   - Формирует событие `ConsumptionEvent` с уникальным event_id, user_id, amount, resource_type и текущим виртуальным временем (event_timestamp).
   - Публикует событие в Брокер сообщений.
6. На экране появляется toast-уведомление: *"Событие опубликовано в брокер: списание 5 ГБ для User #123"*.

**Сценарий взаимодействия (Запуск аномалии):**
1. Пользователь выбирает пользователя "User #123".
2. В блоке "Мгновенные действия" нажимает карточку `[Запустить аномалию]`.
3. Вводит объем: `15` ГБ (что составляет 20% от лимита пользователя).
4. Нажимает кнопку `[Запустить]`.
5. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/events/anomaly/user/start` с ID пользователя, типом ресурса и объемом.
   - Запускает внутренний таймер, который в течение 6 виртуальных часов будет публиковать в брокер события с флагом `is_anomaly: true`, равномерно распределяя объем 15 ГБ.
6. На экране появляется toast-уведомление: *"Аномалия запущена: 15 ГБ за 6 виртуальных часов"*.
7. В таблице "Активные генерации" появляется новая строка:
   - Пользователь: User #123 (+79991234567)
   - Тип: Аномалия
   - Режим: TRAFFIC 15GB (за 6 часов)
   - Статус: Активна
   - Запущено в: [текущее виртуальное время]
   - Действия: Кнопка `[Стоп]`

**Сценарий взаимодействия (Остановка аномалии через таблицу):**
1. Пользователь видит в таблице "Активные генерации" строку с аномалией для User #123.
2. Нажимает кнопку `[Стоп]` в этой строке.
3. **Система (Генератор):**
   - Отправляет `POST /api/v1/generator/events/anomaly/user/stop` с ID пользователя.
   - Останавливает внутренний таймер аномалии. События больше не публикуются.
4. На экране появляется toast-уведомление: *"Аномалия остановлена для User #123"*.
5. Строка удаляется из таблицы "Активные генерации".

**Сценарий взаимодействия (Отправка запоздалого события):**
1. Пользователь выбирает в выпадающем списке "Пользователь #123".
2. В блоке "Мгновенные действия" нажимает карточку `[Отправить запоздалое событие]`.
3. Вводит объем: `1.5` ГБ, и "Часов назад": `3`.
4. Нажимает кнопку `[Отправить]`.
5. **Система (Генератор):**
   - Вычисляет event_timestamp = (Текущее виртуальное время - 3 часа).
   - Формирует событие `ConsumptionEvent` с уникальным event_id, user_id, amount, resource_type и вычисленным event_timestamp.
   - Публикует событие в Брокер сообщений.
6. На экране появляется toast-уведомление: *"Запоздалое событие успешно опубликовано в брокер (event_timestamp: 12:30)"*.

## 3.4. Вкладка "Справочники"
**Цель:** Создание тестовых тарифов (ServicePackage) для привязки к группам.

**Элементы интерфейса:**
1. **Форма создания тарифа**:
   - Поле "Название тарифа" (текст, обязательно).
   - Поле "Общий трафик (ГБ)" (число, min=0, step=0.01, обязательно).
   - Поле "Общие минуты" (целое число, min=0, обязательно).
   - Кнопка `[Создать тариф]` (Primary).
2. **Список созданных тарифов** (таблица под формой):
   - Колонки: ID, Название, Трафик (ГБ), Минуты.

**Сценарий взаимодействия (Создание тарифа):**
1. Пользователь заполняет форму:
   - Название: "Семейный"
   - Трафик: `50` ГБ
   - Минуты: `500`
2. Нажимает кнопку `[Создать тариф]`.
3. **Система (Генератор):**
   - Отправляет `POST /api/v1/tariffs` с введенными данными (название, трафик, минуты).
4. При успехе (201 Created):
   - Форма очищается.
   - Таблица снизу обновляется (добавляется новая строка с созданным тарифом).
   - Появляется toast-уведомление: *"Тариф 'Семейный' успешно создан"*.
1. При ошибке (400 Bad Request):
   - Поля с неверными данными подсвечиваются красным.
   - Под формой выводится сообщение об ошибке от сервера (например, "Название тарифа уже существует").

# 4. Общие правила UI
1. **Валидация полей**: Все обязательные поля помечены звездочкой. Валидация происходит на стороне клиента до отправки запроса.
2. **Обработка ошибок**: Все ошибки от сервера отображаются в виде toast-уведомлений красного цвета или текста под полями формы.
3. **Загрузка данных**: При выполнении запросов отображается индикатор загрузки (spinner) на соответствующей кнопке или в таблице.
4. **Обновление данных**: Таблицы на вкладке "Дашборд" обновляются автоматически при переходе на вкладку. Для ручного обновления используются кнопки `[Обновить]`.
5. **Toast-уведомления**: Все успешные действия сопровождаются зеленым toast-уведомлением в правом верхнем углу экрана, которое исчезает через 3 секунды.
