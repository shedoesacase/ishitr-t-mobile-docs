
# 1. Домены, таблицы
## 1. Домен: Пользователи и Аутентификация

### Таблица 1. User

 **Хранит информацию о всех пользователях системы. Каждый пользователь идентифицируется по уникальному номеру телефона.**

| **№** | **Название** | **Комментарий**   |
| ----- | ------------ | ----------------- |
| 1     | user_id      | PK, автоинкремент |
| 2     | phone_number | unique            |
| 3     | created_at   |                   |

## Таблица 2. AuthCode

**Хранит временные коды подтверждения для авторизации пользователей. Коды имеют ограниченный срок действия (3 минуты) и могут быть использованы только один раз.**

| **№** | **Название** | **Комментарий**                                                                                                                  |
| ----- | ------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 1     | id           | PK, автоинкремент                                                                                                                |
| 2     | user_id      | FK на таблицу 1                                                                                                                  |
| 3     | code         | 0000                                                                                                                             |
| 4     | expires_at   | +3 минуты к времени записи                                                                                                       |
| 5     | is_used      | По идее в реальном приложении это нужно, чтобы отмечать, использовался ли код и можно ли его другому пользователю передать. BOOL |

### Таблица 3. UserSession

**Хранит активные сессии пользователей с токенами доступа (access и refresh). Позволяет управлять авторизацией и принудительно завершать сессии при выходе из аккаунта.**

| **№** | **Название**  | **Комментарий**                                          |
| ----- | ------------- | -------------------------------------------------------- |
| 1     | id            | PK, автоинкремент                                        |
| 2     | user_id       | FK                                                       |
| 3     | access_token  | хэш-строка активного маркера доступа, unique             |
| 4     | refresh_token | хэш-строка реального refresh токена, unique              |
| 5     | expires_at    | дата и время, в которое истечет refresh                  |
| 6     | revoked_at    | дата и время, в которое был отозван код, изначально NULL |

## Домен 2. Семейные группы и Роли
### Таблица 4. FamilyGroup

**Хранит информацию о созданных семейных группах. Каждая группа имеет владельца и статус (активна или расформирована).**

| **№** | **Название** | **Комментарий**                                                |
| ----- | ------------ | -------------------------------------------------------------- |
| 1     | id           | PK, автоинкремент                                              |
| 2     | owner_id     | FK на таблицу 1, UNIQUE                                        |
| 3     | status       | ENUM(ACTIVE, DISBANDED)                                        |
| 4     | created_at   | дата и время, опционально, пока не вижу смысла в этом атрибуте |

### Таблица 5. GroupMember

**Хранит связь между пользователями и группами с указанием их ролей (владелец или участник) и статусов участия. Позволяет отслеживать историю вступления и выхода участников.**

| **№** | **Название** | **Комментарий**               |
| ----- | ------------ | ----------------------------- |
| 1     | id           | PK, автоинкремент             |
| 2     | group_id     | FK на таблицу 4               |
| 3     | user_id      | FK на таблицу 1               |
| 4     | role         | ENUM(OWNER, MEMBER)           |
| 5     | status       | ENUM(ACTIVE, LEAVE, EXCLUDED) |
| 6     | joined_at    | Дата и время                  |

## Домен 3. Тарифы, Периоды и Лимиты
### Таблица 6. ServicePackage

**Справочник доступных тарифных планов с общим объемом минут и трафика. Определяет, какие ресурсы получает группа при подключении тарифа.**

| **№** | **Название**  | **Комментарий**   |
| ----- | ------------- | ----------------- |
| 1     | id            | PK, автоинкремент |
| 2     | name          | Название тарифа   |
| 3     | total_trafic  | Всего трафика     |
| 4     | total_minutes | Всего минут       |

### Таблица 7. GroupSubscription

**Хранит информацию о том, какой тариф подключен к конкретной группе и в какие даты действует расчетный период. Позволяет отслеживать историю смены тарифов.**

| **№** | **Название** | **Комментарий**                                                     |
| ----- | ------------ | ------------------------------------------------------------------- |
| 1     | id           | PK, автоинкремент                                                   |
| 2     | group_id     | FK на таблицу 4                                                     |
| 3     | package_id   | FK на таблицу 6                                                     |
| 4     | period_start | Дата и время подключения тарифа                                     |
| 5     | period_end   | Дата и время(всегда указывает на конец текущего расчетного периода) |

### Таблица 8. UserLimit

**Хранит индивидуальные лимиты потребления для участников группы (в минутах или трафике). Позволяет владельцу ограничивать использование ресурсов конкретными участниками.**

| **№** | **Название**  | **Комментарий**        |
| ----- | ------------- | ---------------------- |
| 1     | id            | PK, автоинкремент      |
| 2     | user_id       | FK на таблицу 1        |
| 3     | resource_type | ENUM(TRAFFIC, MINUTES) |
| 4     | limit_value   | Абсолютное значение    |
| 5     | is_active     | Опционально            |

## Домен 4. Балансы и Потребление

### Таблица 9. GroupPackageBalance

**Хранит текущий остаток общего пакета ресурсов (минуты и трафик) для группы в рамках расчетного периода. Обновляется при каждом потреблении участников.**

| **№** | **Название**      | **Комментарий**          |
| ----- | ----------------- | ------------------------ |
| 1     | id                | PK, автоинкремент        |
| 2     | group_id          | FK на таблицу 4          |
| 3     | period_id         | порядковый номер периода |
| 4     | remaining_minutes | остаток                  |
| 5     | remaining_traffic | остаток                  |

### Таблица 10. UserUsage

**Хранит фактическое потребление каждого участника группы по типам ресурсов (минуты/трафик) за текущий период. Используется для проверки индивидуальных лимитов и расчета статистики.**

| **№** | **Название**  | **Комментарий**                    |
| ----- | ------------- | ---------------------------------- |
| 1     | id            | PK, автоинкремент                  |
| 2     | user_id       | FK на таблицу 1                    |
| 3     | group_id      | FK на таблицу 4                    |
| 4     | period_id     | порядковый номер периода           |
| 5     | resource_type | ENUM(TRAFFIC, MINUTES)             |
| 6     | used_value    | Сколько использовано(точное число) |

## Домен 5. События, Аномалии и Статистика

### Таблица 11. **ConsumptionEvent**

**Хранит сырые события потребления от внешней системы (генератора). Обеспечивает идемпотентность обработки (защита от двойного списания) и служит источником данных для агрегации.**

| **№** | **Название**    | **Комментарий**                   |
| ----- | --------------- | --------------------------------- |
| 1     | event_id        | PK приходит от генератора, unique |
| 2     | user_id         | FK на таблицу 1                   |
| 3     | group_id        | FK на таблицу 4                   |
| 4     | resource_type   | ENUM(TRAFFIC, MINUTES)            |
| 5     | amount          | Количество                        |
| 6     | event_timestamp | Метка времени                     |
| 7     | processed_at    | Во сколько обработано             |

### Таблица 12. HourlyUsageStat

**Хранит агрегированное потребление по часам для каждого участника. Используется для детекции аномального роста потребления без необходимости сканировать все события.**

| **№** | **Название**  | **Комментарий**                      |
| ----- | ------------- | ------------------------------------ |
| 1     | id            | PK, автоинкремент                    |
| 2     | user_id       | FK на таблицу 1                      |
| 3     | group_id      | FK на таблицу 4                      |
| 4     | period_id     | порядковый номер периода             |
| 5     | resource_type | ENUM(TRAFFIC, MINUTES)               |
| 6     | hour_start    | Начало часа (для выявления аномалий) |
| 7     | amount        | Количество                           |

### Таблица 13. DailyUsageStat

**Хранит агрегированное потребление по дням для каждого участника. Используется для построения графиков статистики и расчета прогноза даты исчерпания пакета.**

| **№** | **Название**  | **Комментарий**          |
| ----- | ------------- | ------------------------ |
| 1     | id            | PK, автоинкремент        |
| 2     | user_id       | FK на таблицу 1          |
| 3     | group_id      | FK на таблицу 4          |
| 4     | period_id     | порядковый номер периода |
| 5     | resource_type | ENUM(TRAFFIC, MINUTES)   |
| 6     | date          | дата                     |
| 7     | amount        | Количество               |

### Таблица 14. ArchivedPeriodUsageStat

**Хранит итоговую статистику потребления группы за завершенные расчетные периоды. Позволяет просматривать историю потребления за прошлые месяцы после сброса счетчиков.**

| **№** | **Название**  | **Комментарий**          |
| ----- | ------------- | ------------------------ |
| 1     | id            | PK, автоинкремент        |
| 2     | group_id      | FK на таблицу 4          |
| 3     | period_id     | порядковый номер периода |
| 4     | total_minutes |                          |
| 5     | total_traffic |                          |
| 6     | archived_at   |                          |


## 6. Домен: Уведомления и Аудит
### Таблица 15. NotificationThreshold

**Хранит настройки порогов уведомлений для пользователей и групп. Определяет, при каком проценте потребления ресурсов отправлять push-уведомления.**

| **№** | **Название**      | **Комментарий**                  |
| ----- | ----------------- | -------------------------------- |
| 1     | id                | PK, автоинкремент                |
| 2     | user_id           | FK на таблицу 1, может быть NULL |
| 3     | Group_id          | FK на таблицу 4, может быть NULL |
| 4     | resource_type     | ENUM(TRAFFIC, MINUTES)           |
| 5     | threshold_percent |                                  |
| 6     | scope_type        | ENUM('USER', 'GROUP')            |

### Таблица 16. NotificationLog

**Хранит историю отправленных уведомлений. Предотвращает повторную отправку одинаковых уведомлений в рамках одного расчетного периода (защита от спама).**

| **№** | **Название** | **Комментарий**          |
| ----- | ------------ | ------------------------ |
| 1     | id           | PK, автоинкремент        |
| 2     | user_id      | FK на таблицу 1          |
| 3     | threshold_id | FK на таблицу 15         |
| 4     | period_id    | порядковый номер периода |
| 5     | sent_at      | оправлено в              |

### Таблица 17.  AuditLog

**Хранит полную историю всех изменений в группе (добавление участников, изменение лимитов, передача прав и т.д.). Позволяет владельцу просматривать, кто и когда вносил изменения.**

| **№** | **Название**   | **Комментарий**                                                                            |
| ----- | -------------- | ------------------------------------------------------------------------------------------ |
| 1     | id             | PK, автоинкремент                                                                          |
| 3     | group_id       | FK на таблицу 4                                                                            |
| 4     | actor_user_id  | кто произвел действие                                                                      |
| 5     | action_type    | ENUM('ADD_MEMBER', 'REMOVE_MEMBER', 'CHANGE_LIMIT', 'TRANSFER_OWNERSHIP', 'DISBAND_GROUP') |
| 6     | target_user_id | по отношении к кому                                                                        |
| 7     | details        | json с деталями                                                                            |
| 8     | created_at     |                                                                                            |

# 2. Описание связей между таблицами

### Домен 1: Пользователи и Аутентификация

| Откуда       | Куда                | Тип связи | Описание                                                                                   |
| ------------ | ------------------- | --------- | ------------------------------------------------------------------------------------------ |
| **User** (1) | **AuthCode** (N)    | 1:N       | Один пользователь может иметь несколько записей кодов авторизации (история запросов кодов) |
| **User** (1) | **UserSession** (N) | 1:N       | Один пользователь может иметь несколько активных сессий (на разных устройствах)            |


### Домен 2: Семейные группы и Роли

| Откуда              | Куда                | Тип связи | Описание                                                                                                                                                                             |
| ------------------- | ------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **User** (1)        | **FamilyGroup** (1) | 1:1       | Пользователь может быть владельцем только одной группы (BR-02)                                                                                                                       |
| **FamilyGroup** (N) | **GroupMember** (N) | N:N       | В одной группе может быть несколько участников (2-4 человека, BR-11). Участник группы может состоять в нескольких группах в разных статусах. Только в одной группе в статусе ACTIVE. |
| **User** (1)        | **GroupMember** (N) | 1:N       | Пользователь может быть участником только одной активной группы (BR-01), но исторически может иметь несколько записей (если выходил и вступал в другую)                              |

### Домен 3: Тарифы, Периоды и Лимиты

| Откуда                 | Куда                      | Тип связи | Описание                                                             |
| ---------------------- | ------------------------- | --------- | -------------------------------------------------------------------- |
| **FamilyGroup** (1)    | **GroupSubscription** (1) | 1:1       | У группы одна активная подписка на тариф в текущий момент            |
| **ServicePackage** (1) | **GroupSubscription** (N) | 1:N       | Один тариф может быть подключен к нескольким группам                 |
| **FamilyGroup** (1)    | **UserLimit** (N)         | 1:N       | В группе могут быть установлены лимиты для разных участников         |
| **User** (1)           | **UserLimit** (N)         | 1:N       | У пользователя могут быть лимиты на разные ресурсы (минуты и трафик) |

### Домен 4: Балансы и Потребление

| Откуда                   | Куда                        | Тип связи | Описание                                                                        |
| ------------------------ | --------------------------- | --------- | ------------------------------------------------------------------------------- |
| **FamilyGroup** (1)      | **GroupPackageBalance** (1) | 1:1       | У группы один баланс общего пакета на текущий период                            |
| **User** (1)             | **UserUsage** (N)           | 1:N       | У пользователя могут быть записи потребления по разным ресурсам (минуты/трафик) |
| **ConsumptionEvent** (N) | **User** (1)                | N:1       | Много событий потребления привязаны к одному пользователю                       |
| **ConsumptionEvent** (N) | **FamilyGroup** (1)         | N:1       | Много событий потребления привязаны к одной группе                              |

### Домен 5: События, Аномалии и Статистика

| Откуда              | Куда                            | Тип связи | Описание                                          |
| ------------------- | ------------------------------- | --------- | ------------------------------------------------- |
| **User** (1)        | **HourlyUsageStat** (N)         | 1:N       | У пользователя много записей почасовой статистики |
| **User** (1)        | **DailyUsageStat** (N)          | 1:N       | У пользователя много записей дневной статистики   |
| **FamilyGroup** (1) | **ArchivedPeriodUsageStat** (N) | 1:N       | У группы много записей архива за разные периоды   |

### Домен 6: Уведомления и Аудит

| Откуда                        | Куда                          | Тип связи | Описание                                                   |
| ----------------------------- | ----------------------------- | --------- | ---------------------------------------------------------- |
| **User** (1)                  | **NotificationThreshold** (N) | 1:N       | Пользователь может настроить несколько порогов уведомлений |
| **FamilyGroup** (1)           | **NotificationThreshold** (N) | 1:N       | Группа может иметь несколько порогов для общего пакета     |
| **NotificationThreshold** (1) | **NotificationLog** (N)       | 1:N       | Один порог может срабатывать много раз (в разных периодах) |
| **User** (1)                  | **NotificationLog** (N)       | 1:N       | Пользователь получает много уведомлений                    |
| **FamilyGroup** (1)           | **AuditLog** (N)              | 1:N       | У группы много записей в истории изменений                 |
