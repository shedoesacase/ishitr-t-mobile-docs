# 1. Введение и цели

Генератор — это внешний инструмент для генерации синтетических данных, имитирующий работу реальной телеком-сети. 
Основные цели использования:
- Тестирование бизнес-логики и корректности расчетов (списание баланса, проверка лимитов).
- Проверка временных триггеров и фоновых задач (смена расчетного периода, детекция аномалий) без ожидания реального времени.
- Демонстрация работы системы и отрисовки графиков статистики.

# 2. Режимы работы генератора

- **2.1. Фоновая генерация (Реальное время):** 
  Генератор в реальном времени создает непрерывный поток данных, имитирующий фоновое потребление трафика и минут пользователями (например, обновление приложений, фоновая синхронизация). Интервал отправки событий настраивается.

- **2.2. Ускорение времени (Virtual Clock):** 
  Генератор глобально ускоряет время для всей системы. Режим применяется ко всем сервисам Backend, базам данных и фоновым планировщикам одновременно. 
  *Архитектурное ограничение:* Персональное ускорение времени для отдельных пользователей или групп не поддерживается ввиду критического усложнения архитектуры (необходимости передачи контекстного времени в каждый SQL-запрос и фоновую задачу). Для изоляции тестовых сценариев рекомендуется использовать отдельные развертывания Backend-сервиса. Коэффициент ускорения выставляется вручную через интерфейс Генератора.

- **2.3. Мгновенные действия (Ручное управление):** 
  Режим для быстрого smoke-тестирования. Включает в себя:
  - Отправку пачки событий для мгновенного изменения баланса (симуляция потребления за месяц за секунду).
  - Ручной триггер специфичных событий (аномальный скачок, запоздалое событие).

# 3. Архитектура и интеграция

- **3.1. Взаимодействие с Backend:** 
  - **Управление и справочники:** Взаимодействие через REST API (создание тарифов, управление временем, чтение списка активных пользователей и групп).
  - **События потребления:** Генератор публикует события (ConsumptionEvent) напрямую в Брокер сообщений (согласно UC-04), откуда их забирает Backend-обработчик.

- **3.2. Требование к Backend (Паттерн Virtual Clock):** 
  Время внутри системы является синтетическим и единым. Использование стандартных системных функций времени (например, `NOW()` или подобное) строго запрещено. Все компоненты, зависимые от времени (токены сессий, расчетные периоды, TTL кодов авторизации, планировщики), должны получать текущее время через единый внутренний сервис, управляемый Генератором.
- **3.3. Интерфейс Генератора:** Управление генератором происходит через Web-страницу, по средствам кнопок и полей ввода.

# 4. Генерируемые сущности и сценарии

- **4.1. Справочные данные и пользователи:** 
  - Создание и управление Тарифами (Таблица 6).
  - Генератор должен уметь читать из Backend список активных Пользователей (Таблица 1) и Семейных групп (Таблица 4), чтобы знать, для кого именно генерировать трафик.

- **4.2. События потребления:** 
  Генерация стандартных событий потребления трафика и минут (UC-04) с уникальными `event_id` для проверки идемпотентности (BR-04).

- **4.3. Специфичные сценарии:**
  - **Аномальный рост:** Генерация частых событий за короткий промежуток времени для проверки BR-15 и UC-08.
  - **Запоздалые события:** Отправка событий с `event_timestamp` в прошлом для проверки BR-16 и UC-05.
  - **Сценарий "Поездка/Роуминг":** Изменение паттерна потребления (например, более частые события малого объема или симуляция задержек).

# 5. Ограничения

- **5.1. Код авторизации:** В синтетической среде код авторизации всегда жестко задан и равен "0000" (согласно BR-20).
- **5.2. Финансовые транзакции:** Сервис не генерирует и не обрабатывает реальные финансовые транзакции.
- **5.3. Создание пользователей:** Создание пользователей происходит исключительно через форму регистрации в мобильном приложении (UC-16). Генератор только читает их данные.
- **5.4. Создание семейных групп:** Семейные группы создаются и управляются исключительно через мобильное приложение (UC-01, UC-03).
- **5.5. Управление реальной сетью:** Генератор не управляет реальной сетью, реальными тарифами и реальными абонентами. Все данные вымышлены.
